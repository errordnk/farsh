# farsh без панелей = настоящий шелл пользователя

## Цель

Без панелей (Ctrl+O) farsh — это голый шелл, прописанный пользователю в ОС. Пользователь не должен заметить разницы с запуском этого шелла напрямую: ни в выводе, ни в клавишах, ни в мыши, ни в истории терминала, ни в поведении программ (vim, less, micro, tmux, ssh, scp). На Linux/macOS farsh можно прописать в `/etc/shells` и в passwd (`chsh`), и всё должно работать, включая `ssh host cmd`, scp, sftp и rsync.

## Что сейчас не так

| Где | Сейчас | Чем отличается от голого шелла |
|---|---|---|
| Вывод | Байты PTY разбирает `vt100`, farsh рисует свою сетку диффом | Терминал получает перерисовку, а не поток шелла. Теряются OSC 7 (папка вкладки Som), заголовок, OSC 8, форма курсора, OSC 52, SRP/APC, синхронный вывод. Нет reflow при ресайзе. История терминала появилась только благодаря `push_scrolled` (коммит 8f65df6) |
| Ввод | crossterm разбирает клавиши, `keys::encode` кодирует их заново упрощённым xterm | Теряются Ctrl+Shift-сочетания, AltGr, win32-input-mode, kitty keyboard. Вставка не bracketed |
| Ctrl+O | farsh забирает его всегда | Отнимает Ctrl+O у vim, less, micro и у bash (operate-and-get-next) |
| Мышь | farsh переключает захват сам (коммит e7f412f) | Правильно только наполовину: режимы мыши должна задавать программа в шелле, а не farsh |
| Запуск | Понимает только `--elevation` | Нет `-c`, `-l`, `-i`, нет login-режима (`argv[0]` с `-`), нет запуска без tty |
| Выбор шелла | `$FARSH_SHELL`, иначе `$SHELL` | Если farsh — login shell, то `SHELL=farsh`, и он бесконечно запускает сам себя |

## Архитектура: два экрана

**Основной экран терминала принадлежит шеллу.** Пока панели скрыты, farsh — прозрачная труба:

- байты PTY без изменений идут в stdout; параллельно их получает `vt100`, чтобы у farsh была копия экрана для панелей;
- байты ввода без изменений идут в PTY; farsh только высматривает в потоке Ctrl+O (см. ниже);
- историю, reflow, выделение, колесо, OSC и режимы мыши делает сам терминал. farsh ничего не перерисовывает и не трогает мышь.

**Панели живут на альтернативном экране.**

- Ctrl+O: farsh запоминает режимы терминала, выставленные шеллом, и переходит на альтернативный экран (`?1049h`). Там он включает свои режимы (мышь, win32-input-mode) и рисует панели поверх копии экрана шелла из `vt100`, как сейчас.
- Пока панели показаны, вывод шелла копится сырыми байтами, а `vt100` по-прежнему его разбирает. Так эхо набираемой команды видно в строке под панелями.
- Ctrl+O ещё раз, или запуск команды Enter: farsh снимает свои режимы, уходит с альтернативного экрана (`?1049l`), возвращает режимы шелла и проигрывает накопленные байты. Терминал получает ровно тот поток, который получил бы без farsh, только с задержкой.

**Режимы терминала шелла** (что вернуть после панелей): `vt100` уже знает о курсорных клавишах приложения, keypad, bracketed paste и режимах мыши. Своё отслеживание нужно для kitty keyboard (`CSI > u` / `CSI < u`), фокуса (`?1004`) и формы курсора (`DECSCUSR`). Это маленький разборщик поверх того же потока, а не второй эмулятор.

**Ctrl+O забирается только на пустом приглашении.** Шелл должен стоять у приглашения без набранного текста (есть счётчик приглашений по хуку OSC 7 и `command_line_is_empty`). Пока работает программа или в строке что-то набрано, Ctrl+O, как и любая клавиша, уходит шеллу. Так ведёт себя Far: пока идёт команда, консоль принадлежит ей.

Распознать Ctrl+O в сыром вводе:

- Linux/macOS: байт `0x0f`, а при включённом kitty keyboard — его CSI-u-форма;
- Windows: запись клавиатуры с VK `O` и Ctrl, которую farsh и так читает из очереди консоли.

## Windows

- **Вывод.** Шелл живёт во вложенном системном ConPTY (правило «только дефолты Windows»). Его VT-вывод farsh пишет в свою консоль как есть, через WriteFile с `ENABLE_VIRTUAL_TERMINAL_PROCESSING`. Внешний conhost передаёт его в Som. Цепочка — два conhost вместо одного. Что-то, например APC/SRP, системный conhost может срезать. Это честный предел дефолтов Windows; записать в `AGENTS.md`.
- **Ввод.** farsh читает записи консоли (как `modkeys` сейчас) и отдаёт их во вложенный ConPTY последовательностями win32-input-mode (`ESC [ Vk ; Sc ; Uc ; Kd ; Cs ; Rc _`), которые conhost принимает всегда. Шелл получает те же нажатия, отпускания, сканкоды и модификаторы, что прислал Som. `keys::encode` остаётся только для того, что набирают сами панели (вставка имени файла и т. п.).
- **Мышь.** Захват включается, если его просит программа в шелле (режим мыши из `vt100`), и при показе панелей. Логику `sync_mouse` оставляем, но без панелей она следует только за шеллом.
- **«Шелл, прописанный в ОС»** на Windows — профиль терминала (Som, Windows Terminal). Login shell в ОС нет.

## Login shell (Linux/macOS)

1. **Какой шелл настоящий.** Порядок: `FARSH_SHELL` → настройка farsh `Shell` в профиле → `/bin/bash` (Linux) или `/bin/zsh` (macOS). Никогда не farsh сам: сравнить канонический путь и имя. `$SHELL` больше не источник: при farsh в passwd там сам farsh.
2. **Login.** Если `argv[0]` начинается с `-` или передан `-l`/`--login`, настоящий шелл запускается тоже как login (`argv[0] = "-bash"`): профиль читает он, как и без farsh.
3. **Неинтерактивный запуск.** Есть `-c`, скрипт в аргументах, или stdin/stdout не терминал. Тогда farsh сразу делает `execvp` настоящего шелла с теми же аргументами: тот же pid, без PTY и без панелей. На этом работают `ssh host cmd`, scp, sftp-subsystem, rsync, `vim :!cmd`, `make SHELL=…`.
4. **`SHELL` для детей.** Внутри farsh `SHELL` указывает на настоящий шелл или на farsh? От этого зависит, что запустят vim `:sh` и новые окна tmux (вопрос ниже).
5. **Страховка от потери входа.** Любая ошибка старта farsh (нет терминала, не создался PTY, паника до первого кадра) → `execvp` настоящего шелла. Сначала пробуем на тестовом пользователе на `deb`. Шелл root не меняем. Путь в `/etc/shells` — `~/.local/bin/farsh` в абсолютном виде (правило «бинарники только в ~/.local/bin»).

## Что убрать из сделанного сегодня

- `push_scrolled`, `Shell::take_scrolled`, колбэк `Scrolled`, `Grid::scroll_up`, проталкивание экрана при старте (коммит 8f65df6): историю делает сам терминал.
- Отрисовку экрана шелла без панелей: без панелей farsh не рисует ничего.
- Из коммита e7f412f оставить переключение флага мыши консоли на Windows (`mouse_capture`); правило «когда захватывать» упрощается до «панели показаны или программа просит».

## Вопросы к пользователю

1. `SHELL` внутри farsh: настоящий шелл (vim `:sh` и tmux дадут голый bash) или farsh (у новых окон tmux тоже будут панели)?
2. Ctrl+O при набранном тексте в строке: отдавать шеллу (bash: operate-and-get-next) или всё равно открывать панели? Far открывает панели и при набранной команде.
3. Предел накопления вывода, пока показаны панели (например, 16 МБ). Что делать при переполнении: отбросить начало или перерисовать экран копией из `vt100`?
