# farsh: F3 и Ctrl+Q через SRP — план (черновик на согласование)

Составлен 2026-11-05 автоматическим запуском. Кода нет, ждёт «ок».

## Что выяснено

- **somsrp как библиотеку взять нельзя.** Он зависит от крейта `terminal`
  (а тот — от `gpui`, `theme`, `settings`, cpal, mlua…) ради трёх мелочей:
  `kitty_graphics_placeholder::encode_cell`, типов `ContentType/ContentMetadata`
  и `ffmpeg_ready()`. Крейт `somsrv` тоже тяжёлый (alacritty_terminal, mlua, ureq,
  smol, zlog и path-зависимости workspace Zed).
- **yazi уже делал это вручную**: `yazi-adapter/src/drivers/srp/` — своя копия
  протокола, pipe, daemon, placeholder (~1600 строк). Копия отстала (там ещё
  `som_srv`, `somcat`). Этот путь даёт расхождение протокола без предупреждения.
- **Пиксельный размер ячейки не нужен.** Som сам вписывает картинку/видео в
  placement с сохранением пропорций (letterbox, `terminal_element.rs` ~1781).
  Значит, farsh просто отдаёт под placement весь прямоугольник вьюера и не делает
  запрос `CSI 16 t` (на Windows ответ всё равно пришёл бы через ConPTY
  нажатиями клавиш). Для видео можно не запускать FFmpeg: somsrp вне Windows уже шлёт
  `Video { width_px: 0, height_px: 0, codec: Unknown }`.
- **Ячейка placeholder'а** = `U+10EEEE` + диакритик строки + диакритик столбца,
  fg = session_id (RGB), цвет подчёркивания (`SGR 58`) = file_id; до 297×297.
  `grid::Cell` в farsh хранит `text: String` (три символа влезут), ширина 1, но
  **цвета подчёркивания у Cell нет**.
- **Som перехватывает ввод над виджетом.** ЛКМ по play/seek идёт в Som раньше
  PTY. `handle_audio_widget_key`: Space (play/pause) и стрелки (только у плейлиста/.cue)
  берёт себе, пока на экране виджет «now playing».
- **`resync_rich_content_placements` на ресайзе** сам переписывает ячейки
  placement'а и может вставлять или удалять строки (ни основной, ни
  альтернативный экран он не различает).
- Признак «мы в Som»: локально есть `SOM_WINDOW_ID` (`TERM_PROGRAM` = `zed`, по
  нему не отличить). Через ssh переменная не доходит.

## Предлагаемая архитектура

1. **Новый лёгкий крейт в som: `srp_client`** (`som/crates/srp_client`, без
   path-зависимостей Zed, только serde/serde_json + windows-sys/libc). В него
   переезжают из `somsrv`: `protocol` (типы сообщений; `somsrv` их реэкспортирует,
   поэтому формат один на всех), `pipe::PipeConnection`, путь к сокету, а из
   `terminal` — `kitty_graphics_placeholder` (encode/decode). Туда же —
   клиентская часть somsrp: `SrvChannel`, `stream_bytes`, `stream_file_from_disk`
   + byte-range responder, `cue.rs`, m3u, разбор аудиотегов/метаданных (symphonia,
   image — под feature). somsrp становится тонкой обёрткой над ним. farsh
   подключает его git-зависимостью на `errordnk/som` с закреплённым rev, а позже
   на него же можно перевести yazi.
   *Альтернатива:* скопировать нужное в farsh, как в yazi, — быстрее, но формат
   разойдётся. Не рекомендую.
2. **Сетка farsh:** в `Cell` добавить `ul: Option<Color>` (SGR 58 в `flush`, входит
   в ключ стиля). Добавить `Grid::place(rect, session, file)`: заполняет прямоугольник
   placeholder-ячейками. Diff отправит их один раз; пока кадр не меняется, ничего
   не шлётся и Som продолжает рисовать. Закрыли вьюер — ячейки затёрты, плюс
   `EndPlayback` для аудио и видео.
3. **Вьюер (`viewer.rs`):** `Viewer` = `Text` (как сейчас) | `Media(Placement)`.
   Тип выбирается по расширению, как у somsrp (gif/jpg/jpeg/png, mp3/flac/ogg/oga,
   mp4/mkv/avi, .cue, .m3u). Остальное открывается текстом. Поток данных — в фоновом потоке
   (как сканирование в qview), UI не ждёт. Рамка/статус-строка Far остаются,
   placement занимает текстовую область. Клавиши одиночные (без модификаторов): Esc/F3/F10 —
   выход, `A`/`S` — следующая аудиодорожка/субтитры (перезапуск с новыми ids, как
   `-a/-s` у somsrp), PgUp/PgDn — следующий/предыдущий файл, как в Far.
4. **Quick view (`qview.rs`):** тот же `Placement` в прямоугольнике пассивной
   панели, при смене файла под курсором старый placement останавливается
   (`EndPlayback`) — как в yazi `stop_playback` при смене превью.
5. **Вне Som:** SRP только при `SOM_WINDOW_ID` и доступном демоне somsrv. Иначе
   медиафайл открывается текстовым вьюером, как сейчас (Far показал бы байты).
   Через ssh — пока тоже текст. Позже можно узнавать Som по ответу XTVERSION.
   Демон: только подключение к существующему, **без `replace_if_stale` и без
   запуска своего**. Новый somsrv убивает сессии, а farsh живёт внутри них.

## Риски, которые проверю тестами до живого теста

- Ресайз: Som делает resync, farsh перерисовывает всё (`Grid::unknown`). Риск —
  строки уйдут в scrollback основного экрана. Проверка: тест в `terminal`
  (Som), который подаёт байты farsh-вьюера и меняет размер. Если сломается:
  F3-медиа на альтернативном экране, а в Som — не делать resync placement'ов,
  нарисованных позиционированием курсора.
- Диалог поверх вьюера частично перекрывает placement: надо проверить, что Som не
  растягивает картинку по оставшимся ячейкам.
- Реальные тесты с демоном — только `SOMSRV_INSTANCE=<тестовый>` /
  `SOMSRV_KEEP_DAEMON=1`.

## Вопросы к тебе

1. Крейт `srp_client` в som (рекомендую) или копия в farsh, как в yazi?
2. Quick view и аудио/видео: Som забирает Space, пока виджет на экране, а
   пробел в командной строке farsh нужен. Варианты: (а) в quick view только
   картинки и GIF, аудио и видео — по F3; (б) в Som перехватывать Space только
   при пустой командной строке — так не выйдет, Som её не видит; (в) в Som
   отдавать клавиши виджету только у верхнего (полноэкранного) placement'а.
   Рекомендую (а) сейчас, (в) потом.
3. `.md` по F3: рендер Som (как `somsrp file.md`) или текст, как сейчас?
4. Выбор дорожек `A`/`S` без FFmpeg в farsh — «вслепую» (по кругу по индексу; как
   Som ведёт себя при несуществующей дорожке, ещё не проверено), или подтянуть FFmpeg для списка дорожек (как
   somsrp на Windows: тяжёлая сборка через vcpkg)? Рекомендую вслепую.
